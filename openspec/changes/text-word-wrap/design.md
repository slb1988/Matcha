# Design

## Context

动机见 proposal.md，行为契约见 `specs/text-word-wrap/spec.md`。现状里与折行相关的约束：

- **文本比较**（`crates/bc-gui/src/text/`）：
  - 两个窗格共享一个 `scroll`（`view.rs`），每帧各自用 egui `ScrollArea::show_viewport` 绘制可见显示行（`render.rs::pane`）。
  - 显示行到纵坐标的映射在 `Projection`（`projection.rs`）：`y_of` / `display_at` / `height` 按固定行高 `RowGeometry.row` 计算，过滤模式下的「N FILTERED LINES」细折叠行用 `fold` 高度，靠 `folds_before` 前缀计数修正。
  - 长行只排版约 4096 字节的水平窗口，起点由 `scroll.x / glyph` 推算，其中 `glyph = font_size * 0.62` 是估算字宽。
  - 点击命中用单行 galley 的 `cursor_from_pos`（`render.rs:512/535`）。
  - 跳转经 `pending_scroll` → `projection.y_of`（`view.rs:1428`）。
- **文本合并**（`crates/bc-gui/src/merge/view.rs`）：
  - 不用 `ScrollArea`，四个窗格手工绘制，共用 `scroll`，约 15 处直接写 `scroll.y / row_height` 和 `rows * row_height`。
  - 排版只看每行前 `LINE_LIMIT = 4096` 字节。
  - 点击命中在 `hit()`（`merge/view.rs:161`）。
- **编辑器**（`text/editor.rs`）与窗格宽度无关：
  - ↑/↓、PageUp/PageDown 按逻辑行和字符列移动，Home/End 定位到逻辑行首尾。
  - 合并视图的输出窗格与输入窗格复用同一 `Editor`。
  - 本设计不改编辑器。
- **规模**：两侧各 100 MB、约 100 万行时仍需可用（`text-compare-view` 的既有要求）。

## Goals / Non-Goals

**Goals:**
- 一个由两个视图共用、可单测的「折行 + 变高行几何」组件；Word Wrap 关闭时退化为现有的固定行高算术，行为与像素输出完全不变。
- 绘制与几何使用同一份断点，保证行高计算与实际绘制一致，不出现溢出或裁切。
- 100 MB 级文件开关 Word Wrap 与调整宽度时不卡死。

**Non-Goals:**
- ↑/↓、Home/End 按视觉行移动（已确定按逻辑行）。
- 工具栏 Wrap 按钮。
- 持久化开关状态。
- 底部 Text Details 面板与差异缩略条（nav bar）的折行：两者仍按源行工作。
- 文本报告/补丁输出折行。
- 表格、十六进制视图。

## Decisions

### D1 共享模块 `bc-gui/src/wrap.rs`：断点计算与行高表分离

```
 wrap::Breaker            每个窗格一个：宽度 + 字体 + 制表宽度 -> 字宽缓存
   breaks(text) -> SmallVec<[u32]>     视觉行起始字节偏移（首段 0 省略）
   count(text)  -> u32                 视觉行数（快路径 + 上限）

 wrap::RowHeights         每个视图一个：按显示行的视觉行数
   units: Vec<u32>        每个显示行的高度，单位为「视觉行」（细折叠行另计）
   prefix: Vec<u64>       前缀和（O(n) 重建；二分查 display_at）
   y_of(row), display_at(y), height(), row_units(row)
```

- 行高以「视觉行单位」的整数存储和累加，像素坐标只在最终换算时乘以行高。这样不会累积 f32 误差，查找结果稳定。
- `Projection` 持有一个可选的 `RowHeights`：Word Wrap 关闭时为 `None`，走原有算术，不改变现状。合并视图直接持有 `RowHeights`，把散落的 `scroll.y / row_height` 统一换成 `y_of` / `display_at` 调用，并顺带收敛成几个辅助函数。
- 备选方案：Fenwick 树，支持 O(log n) 单点更新。没有采用：编辑只改少数行，O(n) 重算前缀和在 100 万行时约 1 ms，复杂度不值得。

### D2 断点：自己算，绘制按段排版

- 不用 egui `LayoutJob` 的 `wrap.max_width`。egui 的折行点和我们为行高表计算的视觉行数无法保证一致，一旦不一致，行高与绘制就对不上。
- `Breaker` 逐字符累加字宽：
  - 记住最近一个空白之后的位置作为「可断点」；
  - CJK 表意文字与全角标点前后都是可断点；
  - 超宽时回退到最近可断点，没有可断点则在当前字符前硬断；
  - 每段至少 1 个字符。
- 绘制时每个视觉行用现有的 `layout()`（语法着色、行内差异、空白可视化）排版该段的字节区间，并按「段起点字节偏移」继续传入 token 和行内差异区间。这与现在的水平窗口共用同一个起点偏移机制。
- 字宽来自 egui `Fonts::glyph_width(font_id, ch)`：ASCII 用 128 项数组缓存，其他字符用 `HashMap` 缓存，在 `font_size` 或 `pixels_per_point` 变化时清空。制表符按「下一个制表位」的列宽展开，列宽取空格的宽度。Visible Whitespace 下空格和制表符的替代字形与原字符同宽（现有 `layout` 已如此），因此不影响断点。
- 行尾标记（` CRLF` 等）不参与折行宽度计算，画在最后一段之后，放不下时被窗格裁切，与参考一致，不为它单独再折一行。

### D3 行高表的建立：快路径 + 预算 + 估算

一行在某窗格的视觉行数计算如下：

1. **快路径**：若 `字节长度 * 最大单字节字宽 <= 文本区宽度`，且该行不含 `\t`（用 `memchr` 检查），记为 1，不逐字符扫描。
   - 「最大单字节字宽」取 ASCII 字宽，以及 2/3/4 字节序列中已观察到的「字宽 / 字节数」中的最大值，作为保守上界。CJK 是 3 字节约 2 列，比值低于 ASCII，因此不会误判。
   - 这样绝大多数普通代码行都走快路径。
2. 否则用 `Breaker::count` 精确计算；超过 `WRAP_CAP = 10000` 时截断为 10000。

对齐行的单位数 = 各窗格计数的最大值；缺失侧计 1，细折叠行另计。

宽度变化时的重建按工作量分两档：

- 需要精确计算的总字节数 ≤ 16 MB：当帧同步算完。
- 超过 16 MB：未精确计算的行先用估算值 `ceil(字节数 * 平均字宽 / 宽度)`。每帧对视口及上下各一屏范围内的行精确计算并替换估算值，其余行在后续空闲帧中分批精确计算，每帧约 4 ms 预算，用 `request_repaint` 驱动。

估算值只会让滚动条比例和远处跳转的位置略有偏差，因为进入视口前会被精确值替换，所以可见内容始终正确。

### D4 滚动锚定

纵向位置在内部以「锚点显示行 + 行内像素偏移」表达。行高表重建（开关、宽度变化、估算被精确值替换）前记录锚点，重建后用 `y_of(anchor) + offset` 还原，偏移被钳在新行高之内。这同时满足 spec 中「视口顶端的对齐行保持不变」和「估算替换不跳动」。

开关 Word Wrap 也按同样方式锚定顶端行。

### D5 光标与查找命中的可见性

- `pending_scroll` 只能定位到显示行。新增一种「定位到显示行内第 k 个视觉行」的待滚动请求。
- 光标移动、编辑、查找命中后，用 `Breaker::breaks` 算出光标字节所在段号 k：
  - 若 `y_of(row) + k * 行高` 不在视口内，就最小滚动使其可见；
  - 查找命中仍沿用现有的上下文留白规则。
- Word Wrap 关闭时 k 恒为 0，行为不变。

### D6 绘制与命中

- 一个对齐行占 `units * 行高` 像素：
  - 底色、斜线填充与当前行底线按整行高度绘制；
  - 行号栏内容只在首个视觉行绘制，箭头命中区也只在首个视觉行。
- **可见段裁剪**：只为与裁剪区相交的视觉行排版 galley。10000 段的超长行一帧最多排版一屏的段。断点数组按 (窗格, 源行, 宽度, 内容版本) 放进一个小 LRU 缓存（约 256 项），避免每帧对超长行重新扫描。
- **点击命中**：先由 y 求出显示行与段号；超出本窗格该行段数时放在行尾；再在该段 galley 上调用 `cursor_from_pos`，结果加上段起点字节偏移。
- **选区**：对每个可见段分别求与选区的交集并高亮。
- **截断提示**：本窗格该行计数被截断时，在第 10000 段末尾用弱色文字画「行过长，余下 N 个字符未显示」。
- Word Wrap 开启时，`need_hscroll`（文本比较）与 `max_x`（合并）强制为 0 / false，`scroll.x = 0`，横向滚轮增量被丢弃；4096 字节水平窗口逻辑只在关闭时生效。
- 合并视图开启时，显示不再受 `LINE_LIMIT` 截断，行内差异仍只算前 4096 字节，超出部分按普通着色。

### D7 失效与增量更新

| 事件 | 处理 |
|---|---|
| 编辑某侧若干源行 | 对受影响的显示行重算该侧计数，重算前缀和（O(n)） |
| 重新对齐完成、显示过滤或 Context 展开变化（`Projection` 重建） | 整表按 D3 重建，D4 锚定 |
| 窗格宽度、字号、制表宽度、行号栏显隐变化 | 清空字宽缓存（仅字号变化时）与断点 LRU，整表按 D3 重建 |
| 开关 Word Wrap | 开启时建表，关闭时丢弃（`None`） |

宽度以文本区像素宽度向下取整后比较，避免亚像素抖动触发重建。

## Risks / Trade-offs

- [自算断点与 egui 实际字形排版存在亚像素差异，导致末字符被裁切] → 断点判断时把可用宽度减去 1 px 余量。单测用 egui 实际 `Fonts` 测量，比较「按段排版的 galley 宽度 ≤ 文本区宽度」。
- [100 MB 文件拖动分隔线时每帧重建] → 宽度变化时先按 D3 重建，超出预算时用估算表。拖动中只精确计算视口附近的行，松手后的空闲帧补齐。验收用现有 perf probe（内存中的 perf-measurement-recipe）测量开关与拖动耗时。
- [合并视图把固定行高算术换成表查询，可能引入关闭状态下的回归] → 先做「关闭时等价」的重构提交：用 `RowHeights` 的固定高度实现跑通现有全部合并视图测试与视觉快照，再加折行。
- [OUTPUT 窗格整宽，常常只折 1 行，却要跟随输入窗格补高，下排留白多] → 已确认接受，这是对齐的代价。
- [超长行截断后，光标可能落在未显示的部分（用 End 键或查找）] → 视图滚动到第 10000 段并显示截断提示；底部 Text Details 面板仍显示完整当前行，可在那里查看与编辑。
- [f32 像素坐标在极高内容时失去精度（约 > 16M px，相当于 100 万行 × 15 px 以上再加折行）] → 内部用整数单位计算，只在视口附近换算像素。egui `ScrollArea` 的内容高度仍是 f32，100 MB 加折行的场景需要在验收中实测；若出现抖动，文本比较改为像合并视图那样手工绘制可见行，不再依赖 `ScrollArea` 的绝对偏移。

## Migration Plan

纯显示功能，默认关闭，无数据或格式迁移。回滚方式：撤掉 View 菜单项启用即可，共享模块在关闭状态下为等价的固定行高路径。
