# 104 — 文件夹 UI 的后台边界、虚拟配对与验收口径

## 已确认决定

Wave C 经协调者批准，不修改共享核心/作业/文本引擎，不提前合并文本线。

### UI 与 worker

- 文件夹树由单个 std 工作线程独占；GUI 只持有最新的不可变 Arc 快照。
- I/O、内容测试、规划/执行、刷新、预设/日志写入均在 worker；仅可见行由 show_rows 绘制。
- 快照替换用 latest-only 槽，旧大快照在 worker 回收，避免 GUI 销毁十万行缓存造成顿挫。
- 确认使用 Interaction + 单次回复通道；等待期间 GUI 持续绘制，取消/关闭不会被解释为 Yes。
- 同步预览单独保存，纯展开/排序不丢覆盖；失败规则/过滤更新禁止继续执行旧预览。
- 成功同步才更新本视图的元数据基线；未解决冲突不被新基线掩盖，未实施持久化会话。

### Flatten 的实际身份

经协调者确认：
- 虚拟内容结果以左右 NodeId 和两侧 revision 为键，不能写到不相干的物理树行。
- Copy / Move / Exchange 使用画面配对的实际对侧路径。
- 无显示对侧的孤儿沿用原相对路径，不猜测新目录；路径碰撞仍拒绝，不靠循环覆盖“解决”。
- Touch 的对侧时间戳同样取显示配对；同步视图不提供 Flatten。
- 局部刷新以侧限定相对路径查找，避免手动对齐后的左右名称互相遮蔽。
- 重读保留对齐覆盖，Align With 的精确覆盖优先于旧掩码覆盖。

原生黄金已验证：重复文件名按各侧相对路径排序配对，而不是优先内容相同或相同完整路径。
输入变化后重复组可以重新配对；用户应查看工具提示/确认中的真实路径，不把文件名当唯一身份。

### 快速方向与中央内容结果

原生 `binary-newer-different` 样本：同大小、内容不同、左侧晚 5 秒，
XML 的 filecomp status 为 ltnewer。因此：
- 内容不同不抹掉快速测试的较新方向；内容相同仍按 override 设置覆盖快速差异。
- 中央内容结果与左右文件颜色独立；未读取/被 quick-same 跳过显示“.”，不冒充内容相等。
- 版本测试即使 content=size 也可调度；Quick Compare 的 size 不暗中加入时间戳比较。

### UI 取舍与验收

- 路径选择使用 egui 文本框及本视图最近列表；原生系统文件对话框后置，零新增依赖。
- Owner/group/VCS 可选列对当前 local provider 显示不可用，不编造数据。
- 日期列明确显示 UTC；日期过滤/Touch 使用调用方的本地日期上下文。
- 颜色依据帮助页 dir_understanding_the_display 的色块：
  gray #808080、black #000000、purple #6A00D5、red #FF0000；
  teal/yellow 使用对应标准色并用独立通用图形表达，不复制参考产品图标。
- 当前桌面拒绝前台输入。协调者批准 native 窗口/真实 framebuffer 截图 +
  egui Context::run_ui 与 worker 交互回归作为本轮等价验收。
  **物理桌面鼠标/键盘操作：环境受限（桌面锁定），待负责人在可交互桌面人工复测。**
  不尝试解锁；不能将未生效的 PostMessage 鼠标称为通过。
