# 006 — 回收站策略不可静默永久删除

## 问题

SHFileOperationW 的 FOF_ALLOWUNDO 不是绝对的“只回收”承诺。
网络盘、禁用回收站、大小/配额限制等条件下，系统可能无法回收。
仅设置 NOCONFIRMATION 会留下静默永久删除风险。

## 协调者批准的 Wave A 方案

- UNC / 非固定盘：在任何删除调用之前返回 Unsupported。
- 固定本地盘：FOF_ALLOWUNDO 加 FOF_WANTNUKEWARNING；
  需要永久删除时由 Shell 显示明确警告/确认，不静默降级。
- 系统操作取消返回 Unsupported，错误文本明确表示需要单独的永久删除确认。
- 该异常路径可能显示系统 UI，因此本轮不宣称回收站接口在所有配置下都无 UI。
- 后续任务 4.2 对“回收站不可用”的回退 **必须再确认**，
  不得把用户取消当作永久删除许可；本轮没有实施任务组 4。
- 更严格的 headless recycle-only 后端可后续改为 IFileOperation，
  不在本轮扩大 COM 依赖范围，也不手写 FFI。

## 验证边界

ignored 手动测试在本机默认固定盘策略下成功，且用 Shell 回收站命名空间
查询到该文件。没有更改用户回收站配置、清空回收站或故意制造永久删除；
禁用回收站/超配额警告路径由安全 flags 保证，未冒称已做破坏性配置测试。
