# 103 — 操作确认与双向同步基线

## 状态

Wave B 重派中协调者明确批准，供引擎、后续 GUI 与脚本调用方共同遵守。

## 确认

- 普通 Yes/No-to-All 按确认类别缓存；覆盖、覆盖较新、只读、移动、删除、交换分别独立。
- Prompt 没有 Interaction 时默认拒绝。显式 yes-to-all/no-to-all 策略可用于非交互脚本。
- 回收站 Unsupported 的永久删除回退始终独立询问，不复用普通 YesToAll。
  无 Interaction 时跳过，不将系统回收操作取消视为永久删除许可。
- 计划只是快照；执行前重读源/目标元数据，源变化或目标变化时拒绝陈旧计划。
  一个文件的拒绝/失败不授权其父目录删除，更不能递归删除未计划条目。

## 同步基线

Update Both 可接受上次成功同步的每路径、每侧元数据快照。
两侧相对基线均变化时视为冲突并默认 Leave Alone；没有基线时，
Different/无法确定方向的项为冲突。基线不是文件内容历史数据库，
相同大小和时间戳不能证明内容未变；已有 CRC 可参与指纹。
仅在确认执行/刷新成功后由调用方保存新的基线，失败或取消不能自动覆盖旧基线。

## 其他已批准边界

- OpPlan 为纯快照规划。参与操作的未扫描文件夹返回 ScanRequired；
  调用方先通过 LoadDirJob 获取完整 listing，再重建计划，不能绕过过滤盲目递归。
- Exchange 文件夹按过滤后的逐文件动作规划，孤儿移动到对侧。
  文件对先写两份临时副本再发布；发布失败尝试回滚并保留无法恢复的备份路径。
  不承诺整个目录树的事务，也不把部分完成伪装成全量成功。
